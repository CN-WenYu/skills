# Example Deconstruction

First inspect the actual object provided by the user or available with authorization. If the source cannot be accessed, explain the gap and request a screenshot, link, code, or description rather than inventing details.

## Analyze

1. State in one sentence who the object serves, the problem it solves, and its success criterion.
2. Identify its structure or workflow and the choices that create its quality difference.
3. Separate transferable principles from details that depend on a specific brand, business, dataset, or historical context.
4. Convert principles into an executable, checkable list instead of repeating the visible result.

## Output

Produce three to five reusable principles, a prioritized operating checklist, and one low-risk practice or trial. State the conditions under which every principle holds; do not mistake a single successful example for universal causality.
